## 一、整体架构分层

```
┌─────────────────────────────────────────────────────────────┐
│                   用户交互层 (CLI / GUI / API)              │
├─────────────────────────────────────────────────────────────┤
│                   任务规划与执行层 (Planner/Executor)       │
├─────────────────────────────────────────────────────────────┤
│              感知层 (Perception)   │   行动层 (Action)       │
│   - 屏幕截图 / 图像分析           │   - 键盘 / 鼠标控制     │
│   - 系统信息 / 进程列表           │   - 执行 Shell 命令     │
│   - 文件/目录状态                 │   - 打开/操作应用       │
├─────────────────────────────────────────────────────────────┤
│                    记忆层 (Memory)                          │
│   - 短期对话上下文                │   - 长期任务历史        │
│   - 工作记忆 (当前步骤)           │   - 反思总结            │
├─────────────────────────────────────────────────────────────┤
│                    工具与扩展层 (Tools)                     │
│   - 网络请求 / 爬虫               │   - 文件读写 / 解析     │
│   - 代码执行 (Python / Shell)    │   - 外部 API 调用       │
├─────────────────────────────────────────────────────────────┤
│                    安全与沙箱层 (Sandbox)                   │
│   - 敏感操作确认 / 白名单         │   - 操作回滚 / 日志     │
├─────────────────────────────────────────────────────────────┤
│              本地大模型服务 (已部署)                        │
│   - Chat/Completions 接口 (文本+视觉)                      │
└─────────────────────────────────────────────────────────────┘
```

## 二、核心模块详解

### 1. 用户交互层
- **输入方式**：支持自然语言指令（如“帮我把桌面上的几个文档整理到新文件夹”）或结构化任务（JSON）。
- **输出展示**：实时反馈当前执行步骤，可暂停/中断/回滚。
- **权限管理**：初始设定允许的操作范围（如只读/完全控制）。

### 2. 任务规划与执行层（Agent 的“大脑”）
- **Planner**：接收用户目标，将其分解为一系列可执行的子任务（如“打开浏览器 → 搜索 → 下载 → 保存到桌面”）。
- **Executor**：按顺序执行子任务，每步调用感知层获取当前状态，调用行动层执行动作，并检查是否达到预期效果。
- **反思循环**：执行完每一步后，将结果（包括屏幕截图、命令输出）送回 LLM，判断是否成功，若不成功则尝试修正（重试、调整参数、回退）。
- **状态机**：维护任务进度、当前子任务、已完成/待完成列表。

### 3. 感知层（Perception）
- **视觉感知**：定时捕获屏幕截图，利用多模态模型（已部署）理解当前窗口内容、UI元素、文本、图标等。
  - 可结合 OCR（如 Tesseract）提取文字，辅助截图分析。
  - 可定位元素（如“找到右上角的关闭按钮”）。
- **系统状态感知**：
  - 当前前台窗口标题、进程列表、CPU/内存使用率。
  - 文件系统状态（当前目录、最近文件修改）。
  - 网络连通性、剪贴板内容。
- **日志感知**：读取应用日志、错误信息，用于异常诊断。

### 4. 行动层（Action）
- **基本操作**：
  - 鼠标：移动、点击（左/右/双击）、拖动、滚动。
  - 键盘：输入文本、组合键（Ctrl+C/V）、功能键（Enter、Tab）。
- **高级操作**：
  - 执行 Shell 命令（PowerShell / cmd）。
  - 启动/终止应用（通过进程名或路径）。
  - 操作窗口（最大化、最小化、切换）。
  - 文件操作（复制、移动、删除、重命名、解压）。
- **原子性**：每个动作应可记录和回滚（例如保存文件原始状态）。

### 5. 记忆层（Memory）
- **短期记忆**：当前任务的对话历史、上几步的操作和反馈，用于临时上下文。
- **长期记忆**：存储以往任务的总结、常见操作模式、用户偏好，可随使用积累。
- **工作记忆**：正在执行的任务子目标、中间变量（如找到的文件名）。
- **反思记录**：记录失败案例和纠正策略，供后续参考。

### 6. 工具与扩展层（Tools）
- **预置工具**：文件读写、JSON/CSV解析、网页爬取、发送邮件、调用外部 API（天气/搜索）。
- **代码执行**：允许 Agent 生成 Python/PowerShell 代码并执行（需沙箱限制）。
- **可插拔**：用户可自定义添加新工具（如连接智能家居）。

### 7. 安全与沙箱层（Sandbox）
- **操作审批**：高风险操作（删除文件、修改系统配置、执行未经验证的代码）需用户确认。
- **白名单/黑名单**：限制可操作的目录、进程、网络目标。
- **审计日志**：记录所有动作，便于追溯。
- **隔离环境**：若可能，在虚拟环境或容器中执行危险操作。

## 三、核心交互流程（以“整理桌面文件”为例）

1. **用户输入**：“请把桌面上的所有 .pdf 文件移动到 Documents/PDF 文件夹，并按日期重命名。”
2. **Planner** 分解：
   - ① 获取桌面路径；
   - ② 列出所有 .pdf 文件；
   - ③ 检查目标目录是否存在，不存在则创建；
   - ④ 对每个文件，提取修改日期，生成新文件名（如 `2025-01-20_原始名.pdf`）；
   - ⑤ 移动文件。
3. **循环执行**：
   - **感知**：截图/系统信息 → 确认桌面位置；
   - **行动**：执行 `Get-ChildItem` 或 Python 脚本获取文件列表；
   - **LLM 评估**：结果是否合理？如果文件过多，是否要分批？→ 调整计划；
   - **执行移动**：逐文件移动，每步记录日志；
   - **最终校验**：再次扫描目标目录，确认文件已正确迁移。
4. **反馈**：向用户汇报成功迁移了 N 个文件，给出新位置列表。

## 四、关键技术要点

- **多模态融合**：利用视觉模型识别 UI 元素，但要注意延迟和成本（本地模型较快，但仍需优化截图尺寸）。
- **动作空间建模**：需定义一套统一的动作描述（如 `MoveMouse(x,y)`, `Click(button)`, `Type(text)`），LLM 可直接生成结构化指令。
- **规划与反思**：使用“ReAct”或“Plan-and-Solve”等提示范式，引导 LLM 逐步推理，并允许中途修正。
- **错误恢复**：若动作失败（如找不到元素），应尝试重新截图分析、调整坐标、或使用替代方法（如快捷键）。
- **性能优化**：截图和分析频率不要过高（1-2 秒一次），缓存不变的界面状态。
- **人机协同**：复杂任务可请求用户介入（如输入密码、选择文件）。

## 五、部署与运行建议

- 将 Agent 主程序作为常驻服务（类似后台进程），暴露 WebSocket 或 REST API 与前端交互。
- 使用异步事件循环，避免阻塞屏幕操作。
- 日志系统详细记录每一步，便于调试。
- 初始版本可先实现命令行操作和简单 GUI 自动化（如 `pyautogui` + `subprocess`），逐步增加视觉规划。
